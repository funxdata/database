# 05 · 构建与发布

## 本地构建

前置条件：

- Rust stable（edition 2021）。
- C 编译器（`rusqlite` 的 `bundled` 特性需要编译 SQLite C 源码）：
  - Windows：Visual Studio Build Tools（MSVC）。
  - Linux：`gcc`/`clang` 与 `make`。
  - macOS：Xcode Command Line Tools。
- 不需要系统安装 SQLite。

构建命令：

```bash
cargo build --release
```

产物（`Cargo.toml` 中 `name = "database"`、`crate-type = ["cdylib", "rlib"]`，其中 `rlib` 供 `tests/` 与 `units/` 测试引用）：

| 平台 | 文件 |
| --- | --- |
| Windows | `target/release/database.dll` |
| Linux | `target/release/libdatabase.so` |
| macOS | `target/release/libdatabase.dylib` |

测试：

```bash
cargo test           # tests/ 与 units/ 中的 Rust 测试
(cd ts && deno task test)   # Deno FFI 直连动态库的测试（需先 cargo build --release）
(cd ts && deno task check)  # TypeScript 类型检查
```

调试构建：

```bash
cargo build          # target/debug/
cargo check          # 仅类型检查
```

README 使用 `cargo build --release`；仓库已不再包含 `CMakeLists.txt` 与 `build/` 目录。

## 发布元数据 `dytes.json`

```json
{
  "name": "database",
  "uuid": "e754edcb-7046-4ce9-bc85-92e27b82a8ce",
  "version": "1.0.5",
  "description": "system for database management",
  "keywords": ["database", "management"],
  "author": "funxdata",
  "type": "sys",
  "platform-exports": {
    "windows": { "./target/release/database.dll": "database.dll" },
    "linux": { "./target/release/libdatabase.so": "database.so" },
    "macos": { "./target/release/libdatabase.dylib": "database.dylib" }
  }
}
```

- `version` 是发布版本的事实来源；`Cargo.toml` 已同步为 `1.0.5`。
- `platform-exports` 决定发布矩阵与目标文件名。
- `type: "sys"` 影响发布分类路径。

## GitHub Actions

### 1. `test.yml`（测试，可复用）

- 触发：推送到 `main`、Pull Request，或由发布工作流通过 `workflow_call` 调用。
- 步骤：`cargo fmt --check` → `cargo clippy --all-targets -- -D warnings` → `cargo test --all-targets` → `cargo build --release` → 校验导出符号 → 在 `ts/` 下执行 `deno fmt --check`、`deno lint`、`deno task check`、`deno task test`、`deno task smoke`。
- 权限最小化为 `contents: read`。

### 2. `dytes-release.yml`（唯一发布入口）

- 触发：推送 `v*` 标签，或手动 `workflow_dispatch`。
- `prepare` 任务：
  - 读取 `dytes.json` 的 `version`；
  - 校验 `Cargo.toml` 与 `dytes.json` 版本一致；
  - 若为标签触发，校验 `v<tag>` 与版本一致；
  - 读取 `platform-exports` 的键作为发布矩阵（`windows|linux|macos`）。
- `test` 任务：通过 `uses: ./.github/workflows/test.yml` 复用测试工作流。
- `publish` 任务（`needs: [prepare, test]`，矩阵串行）：
  - 安装 Rust stable；
  - 执行 `cargo build --release`；
  - 调用 `dytescn/dytes@v0.1.23` 的 `publish` 命令，按 `platform-exports` 收集并上传产物。

### 发布规则

- 只有 `dytes-release.yml` 一个发布入口；旧的 `linux.yml` / `mac.yml` / `win.yml` 已删除。
- 平台目录统一为 `windows` / `linux` / `macos`，与 `dytes.json` 一致。
- 发布前必须通过 `test.yml`，不再安装 `cmake` / `ninja` / `clang` 等与当前 cargo 构建无关的依赖。
- 标签、`Cargo.toml`、`dytes.json` 三者版本必须一致。

## 版本发布检查清单（建议）

1. 同步更新 `dytes.json` 与 `Cargo.toml` 的 `version`。
2. 本地运行 `cargo test`、`cargo build --release`，并在 `ts/` 下运行 `deno task check`、`deno task test`。
3. 提交并推送 `main`（触发 `test.yml`）。
4. 打标签 `v<version>` 并推送（触发 dytes 发布）。
5. 校验各平台产物名称与 `platform-exports` 一致。

## 本地杂项

- 仓库已移除 `build/`、`crates/`、`publish.exe`、`.vscode/` 等历史遗留目录/文件。
- `tests/` 与 `units/` 分别存放集成测试与 C ABI 测试，可通过 `cargo test` 运行；`ts/` 的 FFI 测试在 `ts/` 目录下执行 `deno task test`。
