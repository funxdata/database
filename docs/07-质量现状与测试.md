# 07 · 质量现状与测试

| 项目 | 现状 |
| --- | --- |
| Rust ABI/协议测试 | `units/`：`ffi_test.rs` 3 个 + `cjson_test.rs` 4 个（`[[test]]` 注册） |

## 测试组织规范

1. **`src/` 中不允许出现测试代码**：不写 `#[cfg(test)]`、`mod tests` 或测试辅助函数。
2. **`mod.rs` 只允许模块声明/包引用**：例如 `pub mod sqlite;`，不写业务逻辑或测试。
3. Rust 集成测试放在 `tests/`；C ABI/协议层测试放在 `units/`，并在 `Cargo.toml` 用 `[[test]]` 注册。
4. TypeScript 测试放在 `ts/`，通过 `Deno.dlopen` 直接加载动态库，禁止 HTTP/`cyctron` 转发。

## 现有测试覆盖

### `units/ffi_test.rs`

- `db_create` → `db_insert` → `db_query` → `db_update` → `db_delete` 全链路。
- 请求校验：非法 JSON（`400101`）、缺 `table`（`400102`）、缺 `sql`（`400104`）。
- `json_out` 为空指针返回 `-1`。
- 每个测试使用唯一库名，并在 `Drop` 中关闭缓存连接、清理 `.db` / `-wal` / `-shm`。

### `units/cjson_test.rs`

- `write_success` / `write_error` 的响应封套。
- `json_out == NULL` 返回 `-1`。
- 载荷超过 1 MiB 返回 `-2`。
- 使用 `MAX_JSON_OUT` 作为边界来源。

### `tests/db_test.rs`

- CRUD 闭环。
- 类型映射：INTEGER/TEXT/REAL/BLOB/NULL。
- 空结果集返回 `[]`、非法 SQL 返回 `Err`。
- 非法库名（`../x`、绝对路径、分隔符等）被拒绝。
- 非法表名被拒绝；保留字表名（`order`）可正常使用。
- 多语句 SQL 被拒绝。
- Unicode 与 10K 长文本可完整往返。
- 重复列名时最后一个同名列生效。
- 非法 schema 失败不影响已有数据。
- 外键约束生效。
- 两个线程并发写入同一库，全部写入成功。

### `ts/run_tests.ts`

- 通过 Deno FFI 调用 5 个符号完成 CRUD。
- 校验错误业务码（`400102`、`500100`、`500101`）。
- 结束后删除测试数据库文件。

### `ts/smoke_test.ts`

- 5 个导出功能各一个冒烟用例：建表、插入、查询、更新、删除。
- 关键校验：缺 `table`、非法库名、非法表名。
- 输出每个用例的 PASS/FAIL 与耗时，结束后清理测试库。

## 运行方式

```bash
cargo build --release   # Deno FFI 需要先产出动态库
cargo test              # Rust 测试
cd ts && deno task test # TypeScript FFI 测试
cd ts && deno task check # TypeScript 类型检查
```

## 尚未覆盖

- 非 UTF-8 TEXT 的替换字符行为。
- 本地 `cargo test` 不校验动态库导出表（由 CI 的 `nm` 检查覆盖）。

## CI

`test.yml` 在推送 `main` 与 Pull Request 时执行：

```text
cargo fmt --check
cargo clippy --all-targets -- -D warnings
cargo test --all-targets
cargo build --release
导出符号校验（应为 5 个 db_*）
(cd ts && deno fmt --check)
(cd ts && deno lint)
(cd ts && deno task check)
(cd ts && deno task test)
(cd ts && deno task smoke)
```

发布工作流通过 `workflow_call` 复用 `test.yml`，测试通过后才进入发布。
