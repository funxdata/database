# 06 · 调用方式与集成约束

## 允许的调用方式

`database` 只以动态库形式交付，**仅允许其它库文件/宿主进程通过 C ABI 直接调用**：

1. 加载 `database.dll`（Windows）、`libdatabase.so`（Linux）或 `libdatabase.dylib`（macOS）。
2. 解析以下 5 个符号：
   - `db_create`
   - `db_insert`
   - `db_update`
   - `db_delete`
   - `db_query`
3. 按 `docs/03-FFI接口规范.md` 传入 JSON 请求、接收 JSON 响应。

集成方式取决于调用方语言：

| 语言/环境 | 方式 |
| --- | --- |
| C / C++ | 直接声明函数并链接/加载动态库 |
| Python | `ctypes.CDLL` |
| Go | `cgo` + `dlopen` |
| Java / Kotlin | JNI / JNA |
| Node.js | `node-ffi-napi`、`koffi` 等 |
| Rust | `libloading` 或声明 `extern "C"` |

## 禁止的调用方式

- **不提供 HTTP 接口**。
- 经 `cyctron` 或任何 HTTP 网关转发的请求**不能调用 database**。
- 仓库中的 `ts/` 脚本使用 `Deno.dlopen` 直接加载动态库调用，不经过 HTTP。
- 本库不监听端口、不解析 HTTP；`cyctron` 侧也不应把请求转发到 database。

需要远程访问时，应由调用方在自己的服务层完成鉴权与业务校验后，再通过本地 FFI 调用本库；本库本身不做网络监听。

## Deno FFI 测试

`ts/` 提供直接调用动态库的示例与测试，不经过 HTTP：

```bash
cargo build --release
cd ts
deno task test      # CRUD、校验错误、缓冲区溢出
deno task check     # TypeScript 类型检查
```

核心封装见 `ts/client.ts`：使用 `Deno.dlopen` 加载库，按 1 MiB 缓冲区收发 JSON。

## 最小调用示例（C）

```c
#include <stdint.h>

typedef int32_t (*db_fn)(const char *json_in, char *json_out);

/* 伪代码：加载动态库并解析符号 */
db_fn db_query = (db_fn)load_symbol("database", "db_query");

char out[1048576];
const char *req = "{\"path\":\"users\",\"sql\":\"SELECT 1\"}";
int rc = db_query(req, out);

if (rc != 0) {
    /* -1: json_out 为空；-2: 响应超过 1 MiB */
} else {
    /* 解析 out 的 JSON，检查 code == 200 */
}
```

## 运行时约束

- **工作目录**：数据库文件写入进程 CWD 下的 `./database/`。宿主必须以预期目录启动，或在调用前切换 CWD。
- **缓冲区**：`json_out` 至少 1 MiB；超过上限返回 `-2`。
- **并发**：连接按线程缓存，WAL 支持多读一写；已设置 5 秒 `busy_timeout`，并发写冲突会等待而不是立即失败。
- **信任边界**：所有 SQL 仅由调用方 lib 内部发起；不要接受来自 HTTP 或不可信用户的 SQL。
- **路径**：`path` 是逻辑库名，已校验 `[A-Za-z0-9_-]{1,64}`，禁止路径分隔符、`..` 与绝对路径。
